# Innovation Radar — research pipeline

Multi-source data pipeline for Orange Business's Innovation Radar: collects
institutional signals (EU procurement, EU R&D funding, UK/Ukraine public
procurement), filters obvious noise with a trained ML model, and classifies
what's left into Vertical x Use Case x Technology "opportunity spaces" using
an LLM.

## Sources

- `ted_collector/` - TED (EU public procurement notices), CPV-mapped.
- `cordis_collector/` - CORDIS (EU Horizon Europe / H2020 R&D funding), mapped via `legalBasis`.
- `ocds_collector/` - OCDS procurement: UK (Find a Tender + Contracts Finder) and Ukraine (ProZorro), both CPV-mapped. Australia (AusTender) is a confirmed dead end - no live query API, see `ocds_collector/README.md`.

Patents (USPTO/EPO) and US SAM.gov were scoped but not built - both need API
credentials nobody registered for. See `dark_corner.md` for the full history
of what was tried, what worked, and known gaps per vertical.

## Pipeline stages

1. **Collect** - each `*_collector/collector/main.py` queries its source across all 14 verticals (recent / ~1 year ago / ~5 years ago), writes into the shared `articles` table (`common/`). Dedup by `url`/`guid`, safe to rerun.
2. **Select corpus** - `opportunity_classifier/collector/select_corpus.py` builds a 600-articles/vertical `classification_pool` (TED backbone, CORDIS/OCDS fill the remainder).
3. **ML noise filter** - `opportunity_classifier/mlfilter/` embeds articles (multilingual sentence-transformers) and scores them with a Logistic Regression classifier trained on the LLM's own past labels, recommending which articles are obvious noise (target: delete as much as possible while losing <=2% of real signal).
4. **Classify** - `opportunity_classifier/collector/main.py` sends everything the ML filter didn't reject to an LLM (NavyAI, `glm-5.1`) for taxonomy classification, skipping anything already classified or ML-filtered out.
5. **Report** - `reports/generate_stats_report.py` and `reports/generate_opportunity_report.py` produce PDF reports from current DB state.

`run_radar.py` (repo root) orchestrates stages 1-4 end to end and writes a
JSON run summary to `logs/radar_runs/`. Run from repo root:

```
python run_radar.py            # full run
python run_radar.py --limit 20 # cap LLM calls, cheap dry run of the whole shape
```

## Setup

```
pip install -r requirements.txt
```

Requires `NAVY_API_KEY` in the environment (NavyAI LLM API key). `NAVY_BASE_URL`
defaults to `https://api.navy/v1` if unset.

`data/` (the SQLite DB and embeddings cache) and `logs/` are gitignored -
they're regenerated by running the pipeline, not checked in.
